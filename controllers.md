# Конфигурации контроллеров

## Контроллер Теплицы (Arduino Uno + ESP8266 UART)

### Скетчи
- Arduino Uno: `client/controller/greenhouse/v1/arduino_uno_greenhouse_uart_controller_v1/`
- ESP8266 proxy: `client/controller/greenhouse/v1/esp8266_greenhouse_wifi_proxy_v1/`

### Назначение
- Arduino Uno читает датчики, управляет реле и отправляет CSV-телеметрию в ESP8266 по UART.
- ESP8266 подключается к Wi-Fi, преобразует CSV в JSON report-contract и отправляет данные на сервер.
- Сервер возвращает `send_interval_seconds`, `digital_outputs`/`relay_*` и `monitor`; ESP8266 преобразует ответ в CSV-команды для Uno.

### Фиксированная распиновка
- `D2` -> `DHT22 DATA`
- `D3` -> `relay_1`
- `D4` -> `relay_2`
- `D5` -> `relay_3`
- `D6` -> `relay_4`
- `D7` -> `TM1637 DIO`
- `D8` -> `TM1637 CLK`
- `D10` -> `ESP TX` (Arduino RX)
- `D11` -> `ESP RX` (Arduino TX через делитель уровня 5V -> 3.3V)
- `A0` -> датчик влажности почвы, аналоговый выход (`soil_moisture_raw`)
- `A1` -> датчик освещенности, аналоговый выход (`light_level_raw`)

### Линии питания
- `5V` -> `DHT22 VCC`, `Relay VCC`, `TM1637 VCC`, аналоговые датчики при совместимом питании
- `GND` -> общая земля всех модулей

### Свободные порты для расширения
- Цифровые GPIO:
  - `D9`, `D12`, `D13`
- Аналоговые GPIO:
  - `A2`, `A3`, `A4`, `A5`

### Примечания
- `D0/D1` оставить под USB Serial и прошивку Arduino Uno.
- `D10/D11` заняты обменом с ESP8266 через `SoftwareSerial`.
- Линия `Arduino TX -> ESP RX` должна идти через делитель уровня или level shifter.
- Реле активны низким уровнем (`RELAY_ACTIVE_LOW = true`).
- При потере облака/ошибке ESP8266 отправляет Uno безопасное выключение всех реле и `monitor=E<status>`.
- TM1637 используется для отображения `monitor` из ответа сервера или локальных ошибок.
- Для всех устройств обязательна общая земля (`GND`).

### Ключи телеметрии (поле `readings[].pin`)
- `air_temperature` -> температура воздуха с `DHT22` (`D2`)
- `air_humidity` -> влажность воздуха с `DHT22` (`D2`)
- `relay_1` -> фактическое состояние выхода `D3`
- `relay_2` -> фактическое состояние выхода `D4`
- `relay_3` -> фактическое состояние выхода `D5`
- `relay_4` -> фактическое состояние выхода `D6`
- `soil_moisture_raw` -> сырое значение `A0`
- `light_level_raw` -> сырое значение `A1`

## Выносной контроллер почвы (ESP32-C3 SuperMini)

### Статус
В текущем дереве `client/controller/` отдельного скетча для ESP32-C3 SuperMini нет. Раздел описывает планируемый/внешний контроллер и не является зафиксированной распиновкой существующей прошивки.

### Назначение
- `soil_moisture_raw` -> сырое ADC-значение влажности почвы
- `soil_temperature` -> температура почвы, опционально

### Примечания
- Контроллер почвы отправляет данные напрямую на сервер по Wi-Fi и регистрируется как отдельный контроллер пользователя.
- Сценарии могут использовать его датчики для управления реле основного Uno-контроллера.
- Калибровка влажности почвы хранится только на сервере в настройках пина.
- ESP32-C3 не хранит `dry/wet` калибровку и не отправляет проценты как основной источник данных.
- Локальные страницы должны повторять подход ESP8266: `/local`, `/status`, `/config`, fallback AP, Basic Auth, `config.txt` и `ca.pem` в LittleFS.

## Контроллер станции (Arduino Uno + ESP8266 UART)

### Скетчи
- Arduino Uno: `client/controller/station/v1/arduino_uno_station_uart_controller_v1/`
- ESP8266 proxy: `client/controller/station/v1/esp8266_station_wifi_proxy_v1/`

### Назначение
Arduino Uno читает датчики станции, управляет 8 реле, показывает `monitor` на TM1637 и обменивается CSV с ESP8266 по UART. ESP8266 отвечает за Wi-Fi, локальные страницы, provisioning/report API и преобразование CSV <-> JSON report-contract.

### Фиксированная распиновка
- `D2` -> `relay_1`
- `D3` -> `relay_2`
- `D4` -> `relay_3`
- `D5` -> `relay_4`
- `D6` -> `relay_5`
- `D7` -> `relay_6`
- `D8` -> `relay_7`
- `D9` -> `relay_8`
- `D10` -> `ESP TX` (Arduino RX)
- `D11` -> `ESP RX` (Arduino TX через делитель уровня 5V -> 3.3V)
- `D12` -> `FS-IR02` digital output (`tank_level`)
- `D13` -> свободен / встроенный LED
- `A0` -> `DS18B20` data (OneWire, `water_temperature`)
- `A1` -> фоторезистор, аналоговый выход (`light_level_raw`)
- `A2` -> `TM1637 DIO`
- `A3` -> `TM1637 CLK`
- `A4` -> I2C `SDA` (`BMP280`: `atm_pressure`, `air_temperature`)
- `A5` -> I2C `SCL` (`BMP280`: `atm_pressure`, `air_temperature`)

### Линии питания
- `5V` -> `Relay VCC`, `TM1637 VCC`, `DS18B20 VCC`, `BMP280`/датчики при совместимом модуле питания
- `3.3V` -> ESP8266 и датчики/модули, которым требуется 3.3V
- `GND` -> общая земля всех подключенных модулей

### Ключи телеметрии (поле `readings[].pin` на сервере)
- `relay_1` -> фактическое состояние выхода `D2`
- `relay_2` -> фактическое состояние выхода `D3`
- `relay_3` -> фактическое состояние выхода `D4`
- `relay_4` -> фактическое состояние выхода `D5`
- `relay_5` -> фактическое состояние выхода `D6`
- `relay_6` -> фактическое состояние выхода `D7`
- `relay_7` -> фактическое состояние выхода `D8`
- `relay_8` -> фактическое состояние выхода `D9`
- `tank_level` -> бинарный уровень бака с `FS-IR02` (`D12`, active low)
- `light_level_raw` -> сырое значение фоторезистора (`A1`)
- `atm_pressure` -> атмосферное давление с `BMP280` (`A4/A5`, hPa)
- `air_temperature` -> температура воздуха с `BMP280` (`A4/A5`)
- `water_temperature` -> температура воды с `DS18B20` (`A0`)

### Примечания
- `D0/D1` оставить под USB Serial и прошивку Arduino Uno.
- `D10/D11` заняты обменом с ESP8266 через `SoftwareSerial`.
- Линия `Arduino TX -> ESP RX` должна идти через делитель уровня или level shifter.
- Реле активны низким уровнем (`RELAY_ACTIVE_LOW = true`).
- `tank_level` инвертируется как active low (`TANK_LEVEL_ACTIVE_LOW = true`).
- Скетч станции нужно синхронизировать с этой целевой распиновкой перед прошивкой.
- При потере облака/ошибке ESP8266 отправляет Uno безопасное выключение всех 8 реле и `monitor=E<status>`.
- TM1637 используется для отображения `monitor` из ответа сервера или локальных ошибок.
