# Контроллер теплицы (Arduino Uno + ESP8266 UART)

## Скетчи
- Arduino Uno: `client/controller/greenhouse/v1/arduino_uno_greenhouse_uart_controller_v1/`
- ESP8266 proxy: `client/controller/greenhouse/v1/esp8266_greenhouse_wifi_proxy_v2/`

## Назначение
- Arduino Uno читает датчики, управляет реле и отправляет CSV-телеметрию в ESP8266 по UART.
- ESP8266 подключается к Wi-Fi, преобразует CSV в JSON report-contract и отправляет данные на сервер.
- Сервер возвращает `send_interval_seconds`, `digital_outputs`/`relay_*` и `monitor`; ESP8266 преобразует ответ в CSV-команды для Uno.

## Фиксированная распиновка
- `D2` -> `DHT22 DATA`
- `D3` -> `relay_1`
- `D4` -> `relay_2`
- `D5` -> `relay_3`
- `D6` -> `relay_4`
- `D7` -> `TM1637 DIO`
- `D8` -> `TM1637 CLK`
- `D9` -> `FACTORY_RESET_BUTTON` (кнопка на `GND`, `INPUT_PULLUP`, active low)
- `D10` -> `ESP TX` (Arduino RX)
- `D11` -> `ESP RX` (Arduino TX через делитель уровня 5V -> 3.3V)
- `D12` -> `INFO_BUTTON` (кнопка на `GND`, `INPUT_PULLUP`, active low)
- `A0` -> датчик влажности почвы, аналоговый выход (`soil_moisture_raw`)
- `A1` -> датчик освещенности, аналоговый выход (`light_level_raw`)

## Линии питания
- `5V` -> `DHT22 VCC`, `Relay VCC`, `TM1637 VCC`, аналоговые датчики при совместимом питании
- `GND` -> общая земля всех модулей
- `POWER_SWITCH` -> физический выключатель в разрыв плюсовой линии питания до DC-DC/платы контроллера; GPIO не занимает

## Управление питанием, сброс и индикация
Это требование считается общим для будущей линейки контроллеров AiDvor, но в текущей итерации применяется только к контроллеру теплицы.

- На корпусе контроллера теплицы должен быть физический выключатель питания. Он полностью отключает питание контроллера и используется для хранения, перевозки, обслуживания и аварийного обесточивания.
- Выключатель питания не подключается к GPIO: это аппаратный разрыв питания, а не логический вход контроллера.
- На корпусе должна быть отдельная кнопка сброса до заводских настроек. Сброс не должен выполняться по короткому случайному нажатию; целевой сценарий — удержание кнопки 5-10 секунд при включенном питании.
- Кнопка factory reset подключается к `D9` и `GND`; вход Arduino Uno работает в режиме `INPUT_PULLUP`, активный уровень — `LOW`.
- После удержания `D9` Arduino Uno отправляет ESP8266 команду `command=factory_reset`, выключает все реле и показывает `rSt` на TM1637.
- После factory reset ESP8266 очищает пользовательскую конфигурацию подключения и идентификации: Wi-Fi SSID/пароль, `controller_id`, provisioning token и API token. Локальные учетные данные админки и пароль fallback AP сохраняются, чтобы пользователь мог зайти на `/config` и задать новые настройки. После очистки устройство перезагружается и переходит в режим настройки/fallback AP.
- Если `setup_ap_password` и `local_password` не заданы или короче 8 символов, ESP8266 поднимает fallback AP с дефолтным паролем `aidvor1234`.
- Кнопку factory reset желательно делать утопленной или доступной через отверстие под скрепку, чтобы исключить случайное нажатие в теплице.
- Кнопка информации подключается к `D12` и `GND`; вход Arduino Uno работает в режиме `INPUT_PULLUP`, активный уровень — `LOW`.
- Короткое нажатие `D12` переключает режим дисплея. В режиме сервера TM1637 показывает `monitor` из ответа сервера. В режиме информации Arduino один раз запрашивает ESP8266 командой `command=status`, ESP8266 отвечает строкой `ip=<адрес>;wifi=<STA|AP|OFF>;rssi=<значение>`, Arduino сохраняет эти значения и циклично показывает `IP`, `WIFI`, `RSSI`. Обычные ответы сервера продолжают применяться для реле и интервала отправки, но серверный `monitor` в режиме информации не выводится на дисплей. Если ESP8266 не ответил на `command=status`, показывается `NOSt`.
- Отдельный программный sleep mode в прошивке не используется. Энергосберегающий режим задается сервером через увеличение `send_interval_seconds`; контроллер продолжает работать по обычному report-contract.
- Отдельный светодиод режима сна на корпус в текущей версии не добавляется. Fallback/setup AP можно показывать на TM1637 как `AP`, нормальную работу — текущим `monitor` или `RUN`.

## Доступ к настройкам в fallback AP
- Если ESP8266 не может подключиться к домашней Wi-Fi сети или после factory reset Wi-Fi настройки очищены, он поднимает точку восстановления `AiDvor-ESP-<chipId>`.
- Пароль точки восстановления выбирается в таком порядке:
  - `setup_ap_password`, если задан и содержит минимум 8 символов;
  - `local_password`, если задан и содержит минимум 8 символов;
  - дефолтный пароль `aidvor1234`.
- После подключения к Wi-Fi сети контроллера открыть страницу конфигурации:
  - `http://192.168.4.1/config`
- Дополнительные локальные страницы:
  - `http://192.168.4.1/local` — локальная панель состояния и управления;
  - `http://192.168.4.1/status` — JSON-статус ESP8266.
- Если браузер запросит авторизацию, использовать `local_login` и `local_password` из `config.txt`.

## Свободные порты для расширения
- Цифровые GPIO:
  - `D13` (резерв под будущий status LED или другое расширение)
- Аналоговые GPIO:
  - `A2`, `A3`, `A4`, `A5`

## Примечания
- `D0/D1` оставить под USB Serial и прошивку Arduino Uno.
- `D10/D11` заняты обменом с ESP8266 через `SoftwareSerial`.
- Линия `Arduino TX -> ESP RX` должна идти через делитель уровня или level shifter.
- Реле активны низким уровнем (`RELAY_ACTIVE_LOW = true`).
- При потере облака/ошибке ESP8266 отправляет Uno безопасное выключение всех реле и `monitor=E<status>`.
- TM1637 используется для отображения `monitor` из ответа сервера или локальных ошибок.
- Для всех устройств обязательна общая земля (`GND`).

## Ключи телеметрии (поле `readings[].pin`)
- `air_temperature` -> температура воздуха с `DHT22` (`D2`)
- `air_humidity` -> влажность воздуха с `DHT22` (`D2`)
- `relay_1` -> фактическое состояние выхода `D3`
- `relay_2` -> фактическое состояние выхода `D4`
- `relay_3` -> фактическое состояние выхода `D5`
- `relay_4` -> фактическое состояние выхода `D6`
- `soil_moisture_raw` -> сырое значение `A0`
- `light_level_raw` -> сырое значение `A1`
