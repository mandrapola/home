# Контроллер сбора данных с выносных BLE-датчиков (ESP-32D)

## Статус
Раздел описывает новый тип контроллера на базе ESP-32D. Скетч, точная распиновка и список поддерживаемых BLE-датчиков будут зафиксированы отдельно после прототипирования.

## Назначение
ESP-32D используется как gateway-контроллер для сбора показаний с выносных датчиков и передачи данных в AiDvor. Контроллер не заменяет существующие Arduino Uno + ESP8266 конфигурации, а добавляет отдельный тип устройства для распределенного мониторинга.

## Основные функции
- Сбор данных с выносных датчиков на основе компонентов Arduino.
- Сбор данных с существующих BLE-датчиков.
- Нормализация показаний в формат `readings[]`, совместимый с серверным report-contract.
- Отправка телеметрии на сервер через `/api/controller/report`.
- Обработка ответа сервера: `send_interval_seconds`, `digital_outputs` и `monitor`.

## Источники данных
- Arduino-based выносные датчики: отдельные модули, которые могут передавать измерения на ESP-32D по выбранному локальному каналу связи.
- BLE-датчики: существующие датчики, обнаруживаемые ESP-32D через BLE scan/connect.

## Серверный обмен
- Контроллер должен регистрироваться и отправлять телеметрию как отдельное устройство пользователя.
- Основной контракт обмена остается общим: `controller_id` + массив `readings[]`.
- Для каждого показания нужно использовать стабильный ключ `readings[].pin`, чтобы сервер мог хранить настройки пина, калибровку, графики и условия сценариев.
- Если конкретный BLE-датчик отдает несколько значений, каждое значение передается отдельным элементом `readings[]`.

## Обработка ответа
- `send_interval_seconds` задает период следующего цикла сбора и отправки данных.
- `monitor` используется для отображения или логирования состояния обмена.
- `digital_outputs` зарезервирован для будущих исполнительных каналов ESP-32D; если локальных выходов нет, команды можно игнорировать безопасно.

## Примечания
- ESP-32D должен хранить только необходимые локальные настройки подключения и идентификации; калибровку и пользовательские параметры датчиков хранит сервер.
- Для production HTTPS используется `https://home.aidvor.ru` и загруженный CA-сертификат.
- При недоступности Wi-Fi желательно повторить подход ESP8266 proxy: fallback AP, локальные страницы конфигурации и статус подключения.
