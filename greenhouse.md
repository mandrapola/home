# Контроллер Теплицы (Arduino Uno + ESP8266 UART)

## 1. Назначение контроллера
Контроллер теплицы предназначен для:
- сбора базовой телеметрии по воздуху и освещенности (`light_level_raw`),
- передачи фактических состояний реле,
- получения команд управления реле от сервера,
- отображения значения `monitor` (код привязки/время/число) на `TM1637`.

Тип контроллера: жестко типизированный (не универсальный). Список пинов и ключей телеметрии фиксирован.

## 2. Датчики, реле и распиновка

### 2.1 Связь с ESP8266
- `D10` -> `ESP TX` (Arduino RX)
- `D11` -> `ESP RX` (Arduino TX через делитель уровня 5V -> 3.3V)
- `GND` -> общая земля Arduino и ESP8266

### 2.2 Датчики
- `DHT22`:
  - `DATA` -> `D2`
  - ключи: `air_temperature`, `air_humidity`
- Аналоговые входы:
  - `A1` -> `light_level_raw`

### 2.3 Реле
- `relay_1` -> `D3`
- `relay_2` -> `D4`
- `relay_3` -> `D5`
- `relay_4` -> `D6`

### 2.4 Дисплей (опционально)
- `TM1637 DIO` -> `D7`
- `TM1637 CLK` -> `D8`

### 2.5 Питание
- `5V` -> `DHT22 VCC`, `Relay VCC`, `TM1637 VCC`
- `GND` -> общая земля всех модулей

## 3. Ключи телеметрии
Контроллер отправляет только эти ключи:
- `controller_id`
- `relay_1`
- `relay_2`
- `relay_3`
- `relay_4`
- `light_level_raw`
- `air_humidity`
- `air_temperature`

## 4. Контракт обмена данными

### 4.1 Протокол
- Транспорт: HTTP
- Provisioning endpoint: `POST /api/controller/provision` с временным bearer token до привязки
- Telemetry endpoint: `POST /api/controller/report` с индивидуальным `api_token` после привязки
- Между `Arduino Uno -> ESP8266`: CSV по UART
- Между `ESP8266 -> server`: JSON в `application/json`

### 4.2 Запрос от Arduino Uno к ESP8266 (CSV)
Пример:

```text
controller_id=019d5529-ceee-7748-b9a8-a2e3ce1e8b8f;relay_1=0;relay_2=1;relay_3=0;relay_4=1;light_level_raw=285;air_humidity=37.0;air_temperature=25.4
```

Требования:
- `relay_*` передаются как фактическое логическое состояние: `1=включено`, `0=выключено`.
- `light_level_raw` передается как `ADC` значение.
- `air_humidity`, `air_temperature` передаются из `DHT22` (если чтение недоступно, используется последняя валидная пара).

### 4.3 Запрос от ESP8266 к server (JSON)
Пример:

```json
{
  "controller_id": "019d5529-ceee-7748-b9a8-a2e3ce1e8b8f",
  "readings": [
    { "pin": "relay_1", "value": 0 },
    { "pin": "relay_2", "value": 1 },
    { "pin": "relay_3", "value": 0 },
    { "pin": "relay_4", "value": 1 },
    { "pin": "light_level_raw", "value": 285 },
    { "pin": "air_humidity", "value": 37.0 },
    { "pin": "air_temperature", "value": 25.4 }
  ]
}
```

Требования:
- `controller_id` обязателен.
- `readings` — массив объектов `{ pin, value }`.
- Передаются только ключи, перечисленные в разделе 3.
- Запрос авторизуется заголовком `Authorization: Bearer <api_token>`.

### 4.4 Ответ от server к ESP8266 (JSON)
Пример:

```json
{
  "send_interval_seconds": 5,
  "relay_1": 1,
  "relay_2": 0,
  "relay_3": 1,
  "relay_4": 0,
  "monitor": "1234"
}
```

### 4.5 Ответ от ESP8266 к Arduino Uno (CSV)
Пример:

```text
send_interval_seconds=5;relay_1=1;relay_2=0;relay_3=1;relay_4=0;monitor=1234
```

Поддерживаемые ключи ответа:
- `send_interval_seconds` — период следующей отправки отчета.
- `relay_1..relay_4` — требуемые состояния выходов.
- `monitor` — значение для отображения на `TM1637`:
  - 4 цифры кода привязки,
  - время `HH:MM`,
  - или числовое значение мониторинга.

### 4.6 Обработка ошибок
- При ошибке подключения или HTTP `>= 400` контроллер:
  - переводит все реле в выключенное состояние,
  - показывает ошибку на `TM1637` (`Err`/`E<code>` в зависимости от типа ошибки).

## 5. Выносной контроллер почвы (планируемый ESP32-C3)

Для датчиков почвы используется отдельный беспроводной контроллер на базе `ESP32-C3 SuperMini`.
Он устанавливается рядом с грядкой/зоной полива, чтобы провод от аналогового датчика влажности почвы до ADC был коротким.

### 5.1 Назначение
- измерение влажности почвы;
- опционально измерение температуры почвы;
- отправка телеметрии напрямую на сервер по Wi-Fi;
- работа как отдельный контроллер пользователя, доступный сценариям вместе с основным Uno-контроллером.

### 5.2 Локальные страницы
ESP32-C3 должен иметь тот же подход к локальному управлению, что и текущий ESP8266:
- `/local` — локальный статус и последние показания;
- `/status` — JSON-статус устройства;
- `/config` — настройки Wi-Fi, сервера, токенов и локального доступа;
- fallback AP при ошибке Wi-Fi;
- Basic Auth для локальной админки;
- `config.txt` и `ca.pem` в LittleFS.

### 5.3 Ключи телеметрии
MVP отправляет на сервер:
- `soil_moisture_raw` — сырое ADC-значение влажности почвы;
- `soil_temperature` — температура почвы, опционально.

### 5.4 Калибровка
- Калибровка влажности почвы хранится только на сервере.
- ESP32-C3 не хранит `dry/wet` калибровку и не отправляет проценты как основной источник данных.
- Сервер преобразует `soil_moisture_raw` в проценты через настройки пина (`moisture_raw_dry`, `moisture_raw_wet`, `moisture_show_percent`).
- Локальная страница ESP32-C3 может показывать только raw-значение до появления синхронизации серверных настроек.
